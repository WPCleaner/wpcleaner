# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

WPCleaner is a Java Swing desktop tool (plus a headless bot mode) for maintenance tasks on MediaWiki wikis: fixing links to disambiguation pages, Check Wiki syntax errors, Linter errors, spelling/typography. Bugs and features are tracked on Phabricator (project "WPCleaner"), not GitHub issues.

All code lives in `WikipediaCleaner/`: `src/` (main), `test/` (JUnit 4), `libs/` (third-party jars, committed to the repo, no Maven/Gradle), `resources/` (bot tasks, launcher/packaging files).

## Build and test

- JDK: `.sdkmanrc` pins Java 21. Ant compiles with `source/target=17`.
- Full build: `cd WikipediaCleaner && ant main`. It also regenerates i18n catalogs and Javadoc, and it **prompts for the code-signing keystore password**, so it can't run unattended. Output goes to `build/dist/` (`full/WikipediaCleaner.jar` is the fat jar).
- `build.xml` has no test or compile-only target. Tests are normally run from the IDE (IntelliJ `.idea/` and Eclipse `.classpath` are both checked in). JUnit 4 is not in `libs/`. The IDE provides it. To compile and run tests from the CLI, supply JUnit 4 + Hamcrest jars yourself:
  ```bash
  cd WikipediaCleaner
  CP="$(find libs -name '*.jar' | tr '\n' ':')$JUNIT_JAR:$HAMCREST_JAR"
  javac -encoding UTF-8 -d /tmp/wpc-classes -cp "$CP" $(find src test -name '*.java')
  cp -r test/org /tmp/wpc-classes/   # test fixture .txt files are loaded from the classpath next to tests
  java -cp "/tmp/wpc-classes:$CP" org.junit.runner.JUnitCore org.wikipediacleaner.api.check.algorithm.CheckErrorAlgorithm002Test
  ```
- Run a bot task: `cd WikipediaCleaner && ./run-task.sh <lang> <taskfile>` (for example `./run-task.sh fr _Daily.txt`). It requires the built jar and `resources/credentials.txt`. This edits a live wiki, so don't run it unless asked.

## Architecture

**Entry points** (`src/org/wikipediacleaner/`): `WikipediaCleaner` (GUI), `Bot` (CLI: `Bot [-credentials file] <wiki> <Action> args…`, where actions include `DoTasks`, `FixCheckWiki`, `FixLintError`, `FixDump`, `UpdateDabWarnings`, …), `Installer`, `DumpDownloader`.

**Wiki definitions**: `api/constants/EnumWikipedia` lists every supported wiki. Each entry is backed by a settings class in `api/constants/wiki/` (`Wikipedia`, `Wikiquote`, `Waze`, …) that gives URLs, language and the name of the on-wiki configuration page. Behavior is largely configured **on the wiki itself**, not in code:
- `WPCConfiguration`: WPCleaner's own settings, read from the wiki's `WikiCleanerConfiguration` page. Keys are typed enums `WPCConfigurationString/Boolean/Long/StringList`.
- `CWConfiguration`: Check Wiki per-error settings (`error_NNN_prio_<wiki>`, `…_whitelistpage_…`, algorithm-specific parameters).
- `WikiConfiguration`: site info fetched from the MediaWiki API (namespaces, magic words, …).
- `FullConfiguration` aggregates them.

**MediaWiki access**: `api/API` is the interface and `api/impl/MediaWikiAPI` is the implementation, obtained via `APIFactory`. The low-level requests live in `api/request/<module>/` (one package per API module: `query`, `login`, `parse`, …, with XML/JSON result parsers). `api/rest` covers the REST API. `MediaWiki` and `MediaWikiController` provide higher-level, multithreaded batch operations.

**Page analysis**: `api/data/analysis/PageAnalysis` parses wikitext once into typed elements (`api/data/contents/`: internal links, templates, tags, comments, titles, magic words, …) and caches them. Algorithms query the analysis instead of re-parsing the text.

**Check Wiki algorithms**: one class per error number, `api/check/algorithm/aNxx/aNNx/aNNN/CheckErrorAlgorithmNNN.java` (for example `a0xx/a00x/a002/CheckErrorAlgorithm002`). `CheckErrorAlgorithms` finds them **by reflection from that naming pattern**. A new algorithm only needs the class in the right package. Classes extend `CheckErrorAlgorithmBase` and implement `analyze(PageAnalysis, errors, onlyAutomatic)` to report `CheckErrorResult`s with suggested replacements. They override `internalAutomaticFix` for bot-safe fixes, and they declare configurable parameters via `addParameters()`/`AlgorithmParameter` (read from `CWConfiguration`).

**GUI**: Swing, under `gui/swing/` (`MainWindow`, `OnePageAnalysisWindow`, `DisambiguationWindow`, …). Long operations run as workers in `gui/swing/worker/` and `gui/swing/basic/BasicWorker`. The same workers are reused by `Bot`.

**Bot tasks**: `resources/tasks/<lang>wiki/*.txt` are scripts of `Bot` actions (and `Set` parameters) that can include other task files. `run-task.sh` executes them through `DoTasks`.

**i18n**: UI strings go through `i18n/GT` (`GT._T("…")`, `GT.__` for plurals, `GT._No` to mark without translating), using gettext. `translation/WikiCleaner.pot` is regenerated by the Ant i18n targets. The `*.po` files come from translatewiki.net (the "Localisation updates" commits), so don't hand-edit translations.

## Tests

Tests live in `test/` and mirror the `src/` packages. Analysis and algorithm tests load real page wikitext from fixture files (`test/.../PageAnalysisTest_<lang>_<title>.txt`) through `PageAnalysisUtils.analyzeAndTestPage`. They get wikis from `EnumWikipediaUtils.getEN()`/`getFR()`, and they inject Check Wiki configuration with `wiki.getCWConfiguration().setWikiConfiguration(new StringReader(...))`, so no network access is needed. `CheckErrorAlgorithmTest.testPerformance` asserts a maximum run time.

## Conventions

- Commit messages for Check Wiki work use the prefix `CW#<number>: …`.
- Never read or commit `resources/credentials.txt`, `resources/certificate/*.p12`, `resources/wmflabs/id_rsa`, `resources/toolforge/`, or `setup.sh` (all gitignored).
